# 使用拆分后的复现提示词

日常只引用根目录的 `prompt.md` 并说明当前任务。入口包含全程约束与路由，八个模块保留原提示词对应章节的详细要求；本文件是使用指南，不必每次加载。

## 可直接复制的调用方式

首次建立规格：

```text
请按 @prompt.md 执行“论文规格”任务。
先核对目录内论文 PDF，交付规格表、歧义/缺失项清单和工程配置。
本次范围止于规格与配置，不启动训练。
```

实现一个阶段：

```text
请按 @prompt.md 执行“数据与物理环境”任务。
先读取已有 reproduction_state.md 中的产物索引与相关规格，
仅加载当前任务需要的模块，完成环境实现和对应测试后更新状态。
```

仅重绘指定图：

```text
请按 @prompt.md 执行“仅重绘图9”任务。
从 reproduction_state.md 定位已保存的评估数据，保持统计口径，
只调整图形样式。若数据不齐，列出缺失项，不启动训练。
```

明确授权完整复现：

```text
请按 @prompt.md 执行完整复现：规格 → 环境 → 算法与测试 →
真实训练 → 检查点评估 → 六图 → 验收与差异报告。
现在先输出论文复现规格表、歧义/缺失项清单和实现配置，
然后创建完整项目并开展可验证的执行。
不要只给伪代码，也不要只描述如何绘图。
按阶段加载模块并持续更新 reproduction_state.md；遇到缺失信息，
按照规格模块区分可声明的工程假设与阻塞项，不隐瞒未完成工作。
```

`@路径` 是支持文件引用的客户端用法。若客户端不支持引用，直接要求助手读取该路径；纯聊天环境需提供入口和本次相关模块的内容，Markdown 链接本身不会自动注入文件。

## 阶段交接

开始实际复现时，将 [状态模板](templates/reproduction_state.md) 复制到项目根目录的 `reproduction_state.md`，填写当前任务。模板不代表已有代码、训练结果或测试通过。

每阶段完成后，仅更新当前状态、产物路径、关键决策、验证结果、阻塞项和下一步；完整日志保留在产物中，避免复制进状态文件。建议状态文件控制在约80行以内，历史细节放入独立报告并保留路径。

新会话读取 `prompt.md`、实际状态文件和当前模块即可继续。更换会话可以减少累积上下文；拆文件本身无法清除已经加载到当前会话的内容。

模块规定需要执行什么，状态记录已经完成什么。调用旧产物前核对配置、数据来源与检查点；文件存在不等于验收通过。

## 模块维护

- `01`：规格、参数来源和原文歧义。
- `02`：表I/II数据、物理环境、成本奖励和交易。
- `03`：四算法、训练迭代、联邦聚合与检查点。
- `04`—`07`：分别对应图5、图6—8、图9、图10。
- `08`：完整交付清单、运行命令和验收要求。

具体公式和参数仅在负责该内容的模块中维护，入口只保留跨阶段约束。不要把所有模块重新合并到 `AGENTS.md` 或状态文件。

原提示词八章正文已保留；末尾的立即全量执行指令迁移为上面的显式完整复现调用。未指定任务时先做规格，读取验收模块不会扩大本次执行范围。此次拆分未创建实验代码或声称执行训练。
