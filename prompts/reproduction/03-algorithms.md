# 三、实现F-MADRL和比较算法

> 按需模块：实现或审计四种算法、联邦聚合、训练预算与检查点。
> 与根目录 `prompt.md` 的全程约束一起使用。

1. 论文明确的主要超参数

training_iterations = 1500
federation_interval = 500
gamma = 0.99
gae_lambda = 0.95
actor_learning_rate = 1e-4
critic_learning_rate = 1e-3
optimizer = Adam

原文运行环境是Python 3.6.8、PyTorch 1.7.1。
采用其他版本时记录实际版本与差异，不能声称运行环境完全一致。

2. 训练迭代与联邦轮次

为匹配图5，横轴对应每个MG的本地训练迭代1—1500。
分为三个500次的阶段。

不能误写成：
1500轮联邦通信，每轮再训练500次。

可将每次迭代采集一个24步episode作为可运行实现约定，
但必须说明论文没有完整规定episode、epoch与PPO内循环的映射。

PPO内部minibatch更新次数不能混充图上的训练迭代。

3. F-MADRL

三个MG各自使用本地PPO，不能集中收集所有MG的原始轨迹后训练一个PPO。

在完成第500和1000次本地训练后：
上传Actor和Critic参数；
按式(21)/Algorithm 1进行等权平均；
广播并替换三个MG的本地参数。

如果策略有可训练log_std等参数，应明确是否属于聚合参数。

第1500次之后是否最终聚合，以及调度采用聚合前还是聚合后模型，
必须作为检查点约定记录，并保存两种版本供核查。

主实现不额外加入：
个性化头、只聚合Actor、动量聚合、数据量加权聚合。

明确记录：
归一化统计如何处理；
Adam状态是否保留或重置；
广播后old policy如何同步；
旧轨迹是否作废。

4. PPO实现

包括：
冻结的old policy、概率比、clipped objective、GAE、Critic。

使用梯度下降优化器时：
actor_loss = -L_C。

Critic目标与式(27)对照说明。
如采用平方误差最小化，明确记录其与式(29)印刷符号的区别。

检查：
动作映射/限幅与log_prob的对应关系；
多维动作联合概率；
TD目标是否停止梯度；
24小时终止时是否bootstrap；
GAE索引和终止掩码。

5. 四种算法

F-MADRL：
本地PPO + 每500次的联邦聚合。

PPO-MADRL：
三个独立PPO，不聚合。

A2C-MADRL：
三个独立A2C，不聚合。

TRPO-MADRL：
三个独立TRPO，不聚合。

不允许把PPO改名冒充A2C或TRPO。

TRPO应有实际的KL约束、共轭梯度和线搜索。
它的策略更新不能简单套用Adam学习率；
TRPO专有参数及公平性处理必须记录。

四算法共享：
同一个环境、数据场景、状态/动作定义、奖励函数、
可比的网络容量和环境交互预算。

F-MADRL与PPO-MADRL尽可能使用相同初始化和外生场景种子，
以隔离联邦聚合的影响。

6. 检查点

保存：
1、50、500、700、900、1400、1500次迭代的模型。

对500、1000以及可能的1500联邦边界，
额外保存pre_fed和post_fed。

同时保存：
优化器状态、完整配置、随机数状态和运行标识。
