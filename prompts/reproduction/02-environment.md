# 二、实现三微电网物理环境

> 按需模块：实现或审计三微电网环境、输入数据、物理约束和交易。
> 与根目录 `prompt.md` 的全程约束一起使用。

1. 场景与输入数据

使用论文修改后的ORNL-MG场景，包含MG1、MG2、MG3。

按Table I实现各MG的常规机组CG和电池BA；
风电、光伏、负荷和电价使用Table II的全部24小时数据。

调度周期24小时，时间间隔1小时。

输出：
data/mg_parameters.csv
data/day_ahead_profiles.csv

逐项核对PDF。
禁止用正弦波、任意随机负荷或其他数据集替代表II。
禁止将该场景改成IEEE 33-bus/69-bus潮流环境。

表II只列出一组风电和光伏序列。
若三个MG共用该序列，应明确记录这一实现解释，不得悄悄按容量缩放。

原表数值及单位标注保留。
涉及功率、能量和成本的工程单位解释单独说明，不得擅自将电价除以1000或改成其他货币。

2. 状态

按照式(12)：

s_t = [
    P_load(t-1),
    P_wind(t-1),
    P_pv(t-1),
    SOC(t-1),
    E_grid(t-1)
]

说明首时刻的上一时刻数据如何构造。

不要擅自给Actor增加：
未来负荷、当小时真实负荷、其他MG的全局状态或时间编码。
这些只能作为单独标记的扩展实验，不能混入原文复现。

3. 动作

按照式(13)：

a_t = [P_CG(t), P_BA(t)]

功率限制：
MG1：P_CG ∈ [0,200] kW
MG2：P_CG ∈ [0,280] kW
MG3：P_CG ∈ [0,200] kW
三个MG：P_BA ∈ [-50,50] kW

P_BA > 0：放电；
P_BA < 0：充电。

动作限幅依据式(14)—(15)。

额外的SOC可行域投影必须说明其依据。
不能只修正SOC数值，却不修正实际执行的电池功率，从而破坏能量一致性。

4. 成本

常规机组成本：

C_CG = a_CG * P_CG**2 + b_CG * P_CG + c_CG

电池成本保留式(8)的结构：

z = P_BA + 3 * P_BA_max * (1-SOC)
C_BA = a_BA * z**2 + b_BA * z + c_BA

不得将电池成本改成k*abs(P_BA)，也不能删除SOC相关项。
明确成本使用哪个时间索引的SOC。

5. SOC与网损

自放电参数：
delta = 0.002

网损系数：
lambda_CG = lambda_REG = lambda_BA = 0.02

按照式(11)：

P_loss = 0.02 * (P_CG + P_wind + P_pv + P_BA)

注意原式中P_BA带符号。
改成abs(P_BA)属于模型修改，必须单独标记。

SOC更新依据论文式(6)—(7)及已经声明的解释。
电池容量不能由±50 kW的功率限额推导出来。

6. 缺额、奖励与绘图符号

按照式(17)，定义交易前缺额：

P_de = P_load - (
    P_CG + P_wind + P_pv + P_BA - P_loss
)

按照式(16)，定义局部奖励：

r_t = -w_C * (C_CG + C_BA)
      -w_de * E_grid(t) * abs(P_de)

w_C和w_de必须有来源或明确的假设标记。
先保存两类成本和失衡惩罚的原始量，再计算加权奖励。
不能为匹配原图的纵轴而事后缩放奖励。

图6—8的Unbalanced demand定义为：

U_t = -P_de
    = P_CG + P_wind + P_pv + P_BA - P_loss - P_load

U_t > 0：余电；
U_t < 0：缺电。

不要直接把P_de用相同符号画入图6—8。

7. 能源交易

按式(19)实现：
优先使用其他MG的剩余电量；
优先选择价格最低的可用卖方；
剩余缺额由配电网补足。

交易量不能超过卖方剩余盈余或买方剩余缺额。
同价时采用明确、可复现的匹配规则。
未明确的售电条件另列假设。

分别记录：
交易前失衡、MG间交易、与配电网交易、交易后余额。

图6—8必须使用交易前失衡，不能使用外部购电补成零的交易后余额。

实际交易费用单独统计。
不要无说明地用交易费用替换式(16)中的奖励。

8. 预测误差

提供两个明确标记的配置：

deterministic：
直接使用表II预测序列。

gaussian_forecast_errors：
风电/光伏预测误差15%，负荷预测误差3%。

“零均值、标准差按逐小时预测值计算、非负截断、
时间之间独立、MG之间独立”等细节必须说明依据。
未完全明确的内容标记为实现解释。

明确哪种配置用于主图，并保留另一配置的对照入口。
